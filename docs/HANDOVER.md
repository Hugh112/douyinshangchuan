# 抖音智能发布中心交接文档

更新日期：2026-08-10
当前正式版本：3.0.4（定时时间输入与提交门禁修复）
产品码：`publisher.douyin`

## 1. 正式基准

`app/app_main.py` 是唯一正式主程序。`app/app_main.pyw` 是源码启动兼容入口，必须与主程序逐字节一致；每次修改后都要比较 SHA256。不要用 v2.1、v2.2.x 或其他历史副本覆盖现有代码。

关键文件职责：

| 文件 | 职责 |
| --- | --- |
| `app/app_main.py` / `.pyw` | GUI、发布 worker、多浏览器编排、排期、日志、在线更新入口 |
| `app/platform_auth.py` | 统一授权登录、会话恢复、心跳、授权状态与遥测 |
| `app/online_updater.py` | 下载、SHA256 校验、安全解压、覆盖更新、历史文件清理和重启 |
| `app/douyin_gui_config.json` | 用户配置；本机保留，不进入 Git 或更新包 |
| `version.json` | GitHub 灾备更新清单 |
| `build_release.ps1` | EXE、更新 ZIP、安装包的一键构建与临时文件清理 |
| `installer/DouyinPublisher.iss` | Inno Setup 安装规则，允许用户自定义安装路径 |

## 2. 启动与数据路径

安装版正式入口是 `DouyinPublisher.exe`，使用 windowed 模式构建，普通启动没有命令行黑框。旧快捷方式仍可指向固定名 `Start_Douyin_Publisher.vbs`；源码调试使用 `debug_start.bat` 查看完整控制台日志。

安装版运行数据目录：`%LOCALAPPDATA%\DouyinPublisher`

- `douyin_gui_config.json`：发布与浏览器配置
- `authorization.bin`：DPAPI 加密授权会话
- `login_preferences.bin`：DPAPI 加密的记住账号/密码偏好

这些文件不放在安装目录，卸载或更新程序文件时不会主动覆盖。源码模式仍读取仓库 `app/douyin_gui_config.json`，维护时禁止修改用户已填写的浏览器、图片、Excel、日志和调试目录。

## 3. 授权与主界面门禁

启动后主窗口先隐藏，再尝试恢复 DPAPI 会话。恢复成功或处于允许的短暂宽限状态后才显示配置主界面；无有效会话时只显示登录窗口。退出账号、授权撤销或强制下线后重新进入登录门禁。

客户端默认每 60 秒根据后台返回策略调度心跳。在线撤销授权会停止任务并弹窗。遥测可记录软件用户、产品、客户端时间、服务端接收时间、会话、任务状态和账号级成功统计；不会上传抖音 Cookie、正文、图片或本地文件路径。

## 4. 发布任务链路

1. 保存并校验运行选项和启用的浏览器队列项。
2. 按表格顺序处理队列；同一浏览器允许出现多次，每一行都有唯一队列 ID。队列表“发布”列为勾选状态，只有勾选行才进入登录检查、任务统计和发布 worker；未勾选行不启动浏览器。
3. 图片总文件夹是全局共享配置；每行必须绑定自己的 Excel、工作表以及立即/定时发布设置。账号内遗留的 `image_dir` 不再覆盖全局图片池。
4. 通过快捷方式或 EXE 启动浏览器，以独立 CDP 端口连接。
5. 无法正确进入创作者发布页时视为掉号，记录状态并切换下一个账号。
6. 新表格使用“城市、标题、文案”列：城市映射共享图片总文件夹下的同名子目录；勾选随机图片时从该城市目录随机选择，未勾选时按文件名排序选择第一张。图片来自文件系统，不读取 Excel 内嵌图片。
7. 文案只读取 `.xlsx`、`.xls`、`.xlsm`。标题可空；不空时写入独立标题框。正文、话题和标题均使用 `page.keyboard.type` 逐字输入。旧无表头单列及旧“标题”单列表头继续兼容。
8. 每行从自己的状态文件和排期序号开始，按该行配置执行立即发布或抖音定时发布；提交后必须确认进入作品管理页，成功提示本身不作为消费内容的依据。
9. 网页操作按“Playwright 语义定位器 → DOM 原生 click → Playwright 真实鼠标 → 坐标兜底”执行，每一步读取实际网页状态校验。失败先按前端次数只重试当前步骤，耗尽后才总体重跑当前作品；最终失败及其他自动暂停原因都会弹窗。
10. 仅确认发布成功后才消费进度，并按配置删除图片或文案。
11. 当前队列项配额完成后关闭本次调用的浏览器进程，再切换下一行；所有队列项结束才完成整轮任务。
12. 停止任务或关闭软件会保留当前队列轮次：重启后跳过本轮已处理账号，当前账号从已成功条数继续；只有用户点击“重置发布进度”才清零。

发布数量只取每行 `posts_per_run`。日期、开始/结束小时、每小时条数和分钟点只生成一轮定时时间点，不是发布量上限；如果计划发布条数超过生成时间点数量，时间点用完后从该轮第一个时间点继续循环，直到完成该队列行的发布条数。每行仍使用自己的状态文件、排期签名和循环进度。

## 5. 界面约束

- 四个标签的宽高不因选中而变化，只改变颜色和字重。
- 四个标签分别拥有独立纵向滚动容器，滚动互不影响。
- 浏览器账号表格有独立横向和纵向滚动条，表格下方账号操作按钮必须完整显示。
- 浏览器账号表格所有列关闭自动伸缩；用户拖动后的列宽保存到配置并在下次启动恢复。
- 第二标签固定为“账号与排期”，顶部显示唯一的共享图片总文件夹，下面显示扩大后的队列表；支持逐行勾选是否发布、全选、全部取消、添加、复制、编辑、删除、排序、快捷方式批量导入及队列全表 Excel 导入/导出。
- “发布中心”承载“等待与检测”“运行选项”和账号轮换开关；单步骤/总体流程重试次数位于“等待与检测”，连续发布条数仅在勾选轮换发布时启用。公共内容与公共抖音发布时间不再显示。
- 任务控制和运行日志固定在标签区域下方，任意标签页都能看到和操作。
- 运行日志保持简单，不增加解释性小字。

## 6. 安全边界

- 不在源码或文档中保存软件用户密码、抖音账号、Cookie 或后台管理令牌。
- Git 忽略用户配置、DPAPI 文件、日志、状态、暂停标记、截图和所有构建 ZIP。
- 更新包必须是相对路径，拒绝绝对路径、`..` 和符号链接。
- 更新器只按 `OBSOLETE_PATHS` 删除明确的历史文件，不删除图片、Excel、日志、状态或调试截图。
- 不固定 Python 安装路径；源码脚本继续使用系统 `py`。安装版自带解释器和依赖。

## 9. v2.5.2 已合入的热补丁与修复

2.5.2 完整包含 2026-08-05 热补丁及本次续跑、列宽修复：

- 账号计划发布条数超过一轮时间点数量时，按同一轮时间点循环复用，不再因“排期容量不足”拒绝保存或自动暂停。
- 浏览器账号队列增加发布勾选列以及全选/全部取消；所有执行入口只处理勾选账号。
- 停止任务或重启软件后恢复同一队列轮次和账号已完成条数；状态文件改为原子替换写入，并清理遗留暂停标记。
- 浏览器队列表列宽按用户拖动结果持久保存，不再被窗口伸缩或重启恢复为硬编码宽度。

2.5.2 已按非强制更新策略发布。后续版本必须继续包含本节热补丁与修复，不得用 2.5.1 或更早包体反向覆盖源码。

## 10. v3.0.0 城市图片与标题格式

- 推荐表头：`城市 | 标题 | 文案`。标题允许为空，文案不能为空。
- `城市`列存在时，每条文案必须填写城市，并与共享图片总文件夹下的子文件夹名称一致；拒绝绝对路径、`..`、斜杠和目录跳转。
- 没有城市表头的旧单列表格继续从图片总文件夹根目录选图；无表头第一行不会被遗漏。
- 每个队列项继续读取自身 Excel 和工作表，多个账号可以共享同一城市图片池。
- 复合进度键由城市、标题和文案共同生成；相同正文但不同标题或城市不会互相误判为已使用。
- 成功删除 Excel 行时优先核对原始行号及城市、标题、文案三项，避免重复正文删错行。

## 11. v3.0.2 轮换、失败恢复与调试截图

- `rotate_accounts_each_post` 控制账号轮换；`rotate_batch_size` 是每次轮到账号时的连续成功条数，实际子任务目标始终为 `min(连续条数, 账号剩余配额)`。
- 轮换账号达到本批目标后立即把控制权交给下一个账号，账号边界不追加发布间隔；浏览器首次轮到时打开，后续复用原 CDP 端口。
- `retry_times` 表示单步骤失败后的重试次数，`overall_retry_times` 表示单步骤耗尽后当前作品总体流程的重试次数。所有发布页面步骤经 `run_publish_step` 执行；总体重试会重新进入发布页并从上传当前图片开始。
- 音乐控制通过主编辑区音乐模块三态校验和右侧音乐面板识别完成；已选音乐直接跳过，列表不依赖“万使用”或固定时长，点击“使用”后短轮询歌曲信息/修改入口。只有音乐弹窗可点击音乐确认按钮，禁止整页搜索“确定/确认/完成”。
- 调试截图按 `music_panel_not_opened`、`music_list_not_loaded`、`music_song_row_not_found`、`music_use_button_not_found`、`music_click_state_not_applied` 区分音乐失败阶段。
- 最终失败把 `last_account_outcome`、`last_account_message`、`run_progress` 和 `run_quota` 写入账号独立状态文件；账号队列运行状态显示最后失败步骤、根因及保留进度。失败账号只跳过本次运行，下次启动仍恢复未完成进度。
- 发布中心的“重试勾选失败账号”只在任务空闲时使用；勾选的失败/掉号/今日上限账号继续原队列轮次、当前内容和累计进度。
- 掉号与今日投稿上限绕过普通重试。今日上限不消费图片/文案、不增加成功数，并在当前运行中跳过该账号。
- 发布任务暂停后允许编辑、重排和勾选队列，也允许全部取消；继续时保存最新队列并清理暂停前后所有暂停标记。
- GUI 正常启动次数记录在 `%LOCALAPPDATA%\DouyinPublisher\debug_screenshot_cleanup.json`。每三次启动只清理调试目录根层、本软件命名格式的截图，不递归删除用户图片。

## 12. v3.0.3 定时发布与界面稳定性修复

- 任务控制区不再横向挤压“重置发布进度”；重置与清空日志放在倒计时右侧的独立操作区，常用任务按钮在正常窗口宽度下完整可见。
- 选择“定时发布”后，优先聚焦实际日期时间输入框，使用 `page.keyboard.type` 写入完整目标时间，失焦后回读校验；网页不允许直接键盘编辑时保留日期面板与 DOM 事件兜底。
- 进入发布设置前先校验发布设置、发布时间和底部发布按钮是否已经可见；已在底部时不执行 DOM 滚动、鼠标滚轮或随机等待。
- DOM 下滑后立即短轮询校验，只有仍未到达底部时才使用真实滚轮兜底，减少无效滚动和等待。

## 13. v3.0.4 定时时间输入与提交门禁修复

- 抖音新版定时单选控件即使不暴露 `checked` 或 `aria-checked`，也会通过“发布时间”同行可见日期时间框确认定时模式已生效。
- 严格等待定时时间框出现；未出现时保存 `schedule_input_not_visible` 截图并停止该步骤，不进入提交。
- 锁定同一个时间 input，先尝试键盘清空和完整输入；只读或受控组件不接受键盘时，按 v3.0.1 的原生 value setter 顺序执行清空、输入、事件通知和回读。
- 定时时间设置步骤必须回读目标值完全一致；底部发布按钮前的最终校验会再次回读，任何不一致都禁止提交。
- 真实测试账号页面已验证旧时间 `2026-08-11 08:17` 经清空后写入 `2026-08-11 08:36`，最终页面回读一致；测试未点击发布。
